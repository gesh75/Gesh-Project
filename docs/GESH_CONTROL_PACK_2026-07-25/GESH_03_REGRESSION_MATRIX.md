The canonical status describes the best-supported **current product outcome**. A verified live fix can therefore be `FIXED AND VERIFIED` even when it is not safely reproducible from M; that separate release-control failure is tracked as `DEPLOY-01`.

## Status and evidence rules

Only the required statuses are used:

- `FIXED AND VERIFIED`
- `PARTIALLY FIXED`
- `OPEN`
- `REGRESSED`
- `NO LONGER REPRODUCIBLE`
- `UNABLE TO VERIFY`
- `RECLASSIFIED — old interpretation → new interpretation`

Evidence labels follow the master prompt:

- `VERIFIED CURRENT` — reproduced in the live application, current code, or a freshly run test.
- `SUPPORTED BY LATEST EVIDENCE` — strong recent evidence, but not a complete current end-to-end proof.
- `HISTORICAL ONLY` — preserved history, not a current conclusion.
- `INFERRED` — reasoned from the available code/data.
- `UNKNOWN / REQUIRES ACCESS` — the required path could not safely or reliably be exercised.

No row is closed merely because a test suite is green. In particular, existing tests can pass while intentionally requiring customer access to `model_book`, `/api/trades`, and `/api/trades/stats`.

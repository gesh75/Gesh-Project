The canonical status describes the best-supported **current product outcome**. A verified live fix can therefore be `FIXED AND VERIFIED` even when it is not safely reproducible from M; that separate release-control failure is tracked as `DEPLOY-01`.

## Status and evidence rules

Only the required statuses are used:

- `FIXED AND VERIFIED`
- `PARTIALLY FIXED`
- `OPEN`
- `REGRESSED`
- `NO LONGER REPRODUCIBLE`
- `UNABLE TO VERIFY`
- `RECLASSIFIED — old interpretation → new interpretation`

Evidence labels follow the master prompt:

- `VERIFIED CURRENT` — reproduced in the live application, current code, or a freshly run test.
- `SUPPORTED BY LATEST EVIDENCE` — strong recent evidence, but not a complete current end-to-end proof.
- `HISTORICAL ONLY` — preserved history, not a current conclusion.
- `INFERRED` — reasoned from the available code/data.
- `UNKNOWN / REQUIRES ACCESS` — the required path could not safely or reliably be exercised.

No row is closed merely because a test suite is green. In particular, existing tests can pass while intentionally requiring customer access to `model_book`, `/api/trades`, and `/api/trades/stats`.

### Current P0 risks

There are exactly two current P0s:

1. **TEN-01:** the customer model book is still derived from real operator brokerage data without a durable curated publication, explicit consent record, immutable version/assignment, or rollback.
2. **TEN-02:** real discretionary trade data and free-text notes remain customer-readable.

The release is also blocked by the P1 financial, build, and deployment-control findings: FIN-03/FIN-04, BUILD-01/BUILD-02, and DEPLOY-01/DEPLOY-02.

### Green-test false positives that must be removed

- `tests/test_customer_leak_sweep.py` requires customer GET routes—including `/api/portfolio`, `/api/trades`, and `/api/trades/stats`—to return 200 and stamps `view=model_book`; it checks transformed numeric sentinels, not whether the dataset should be exposed.
- `tests/test_model_portfolio_boundary.py` proves a field allowlist, but its target is still a request-time publication from the owner snapshot. It does not prove consent, editorial approval, durable immutability, assignment, or independence from owner connectors.
- `tests/test_model_book_reconciliation.py` can reconcile a constructed model output while using incorrect production field semantics; it does not bridge all broker-account sleeves.
- `tests/test_mybook.py` positively asserts that a syntax-valid unknown symbol can be stored.
- chart tests cover backend `max` without asserting the rendered customer control.
- owner-surface tests strip script bodies before inspection and therefore miss initialization-time owner fetches and console failures.
- Track Record tests assert cohort ordering/disclosure, not responsible presentation when return is positive but the quality gate fails.

Until these tests are inverted or supplemented, a green CI run is not evidence that the current P0s are fixed.
